02How it works

The hash is the direction.

Ask a model for a beautiful page and it reaches for the most common look in its training data: Inter, a purple gradient, a centred headline with two buttons. hash-design doesn’t ask for better taste. It takes the choice away.

  1. 1

    Roll

    N hashes from system randomness: crypto.getRandomValues, 32 bytes → SHA-256. %%DEFAULT_COUNT%% by default, 1–%%MAX_COUNT%% if you ask.

  2. 2

    Map

    Fixed rules read each hash’s bytes straight onto design parameters. There is no style library to pick from.

  3. 3

    Freeze

    Each direction becomes a brief: font links, hex values, tokens.css, grid numbers, corners and shadow, plus the global bans.

  4. 4

    Render

    The agent sends one line per direction and stops. On render it builds one independent preview per brief and a compare page.

  5. 5

    Build

    You reply with a number. The agent builds the final page from that brief and checks it with critique_page.

32 bytes, one direction

Each byte drives one parameter, or two split into bits. Pick a byte to see the rule it feeds and what it decided for this hash.

04Scenarios

Not only web pages.

Pass a scenario and a hash keeps its palette, faces, scale, grid, anchor, motif, surface and voice, and gains a format, a canvas and output rules. Byte 28 picks the format; critique_page checks each scenario’s output contract.

06FAQ

Questions

Is it really random? How do I get the same brief again?

Every roll draws from system randomness (crypto.getRandomValues, 32 bytes → SHA-256); seed exists only to reproduce examples and tests. Each brief records its ref (the hash itself), its constraints and the library fingerprint, and get_brief or hash-design brief <ref> rebuilds exactly the same brief.

Will old refs still reproduce after an update?

Within %%ALGORITHM%%, yes, as long as the library fingerprint is the same: adding a font or a primitive changes the fingerprint and can change what a hash maps to. Every brief records both, so a mismatch is detectable. Refs from hash-design/v1 (the 40-branch library) do not reproduce in v2.

Which agents can use it?

Any agent that loads SKILL.md folders, and any MCP client that starts stdio servers. Without MCP, the Skill falls back to the CLI (npx -y hash-design roll …) with the same options. Without the Skill an agent can still call the tools, but nothing tells it to reply briefly, render previews independently and stop for your pick.

Does critique_page guarantee a good page?

No. It is heuristic static analysis: it catches the banned patterns and checks fonts, hex values, radius and shadow against the brief, but it does not render the page. It solves “everything looks the same”; it does not replace design judgement.

Does it need a network connection?

The CLI and the MCP server run locally and make no network requests. The pages they ask for load fonts from Google Fonts; offline or restricted networks need self-hosted fonts or the fallbacks each brief lists.

Is it on npm?

Yes: hash-design has the library, the CLI, the Skill and the MCP server. Releases are published from GitHub Actions with npm Trusted Publishing and provenance.
